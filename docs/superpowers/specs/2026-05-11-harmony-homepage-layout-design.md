# Harmony 首页排版优化设计

## 背景

当前 Harmony 首页已经具备角色库、人格会议、会议纪要等核心能力，但首页信息组织更接近功能列表聚合，首屏缺少明确的主任务聚焦。对于首次进入或回到首页的用户，页面虽然信息完整，但“下一步该做什么”不够突出，视觉层级也没有充分体现“人格会议”作为核心功能的优先级。

本次优化仅针对 Harmony 端首页，目标是在遵循鸿蒙端移动首页设计习惯的前提下，把首页重构为“会议驱动的灵动首页”：既保留效率型工具首页的清晰操作路径，也增强首屏视觉张力和层次感。

## 目标

1. 将“开始人格会议”提升为首页首屏主动作。
2. 让角色选择、议题预览、最近纪要围绕会议主路径组织，而不是并列堆叠。
3. 保留现有首页的内容完整度，但降低首屏认知负担。
4. 视觉风格贴近 HarmonyOS 常见的卡片式、分层式、轻动效式移动体验。
5. 尽量复用现有数据结构和页面路由，避免本次改版引入额外业务复杂度。

## 非目标

1. 不调整后端接口或数据模型。
2. 不改造会议页、角色详情页、创建页等非首页页面。
3. 不引入新的复杂业务流程，例如首页直接完成完整会议配置。
4. 不为了视觉表现增加过重动画或高风险自定义组件。

## 用户意图与首页定位

本次首页优先满足以下使用意图：

1. 用户想尽快进入一次人格会议。
2. 用户希望在进入会议前，快速确认当前角色、议题和最近上下文。
3. 用户希望首页同时保留“继续浏览角色”和“查看最近纪要”的承接能力。

因此首页定位不是纯展示页，也不是信息仪表盘，而是“会议启动工作台”。

## 设计方向

采用“混合型 + 会议优先 + 灵动层次型”方案：

1. 混合型：兼顾操作效率与视觉质感。
2. 会议优先：首屏最大视觉资源给到会议入口。
3. 灵动层次型：使用更明显的主次卡片层级、渐变与轻微动态反馈，但保持专业和可用性。

## 信息架构

首页默认页的结构调整为以下顺序：

1. 顶部欢迎区
2. 首屏主会议 Hero 卡
3. 会议快速配置区
4. 快捷功能入口区
5. 最近纪要区
6. 其余 Tab 内容维持现有分发逻辑

其中，角色库 Tab 与纪要 Tab 依然保留，但首页 Tab 的首屏语义将从“列表页”转为“主任务工作台”。

## 布局方案

### 1. 顶部欢迎区

顶部欢迎区保留用户问候、头像、连接状态，但不再作为页面唯一视觉焦点。

布局要求：

1. 左侧展示问候语、产品名和一句任务导向副文案。
2. 右侧保留具有识别度的用户或角色首字头像。
3. 连接状态与当前角色以轻量状态芯片承接。
4. 整体高度控制在移动端舒适范围内，避免头部过高挤压首屏主内容。

文案方向：

1. 问候语负责建立情绪。
2. 副文案强调“准备开启一场人格会议”而非泛化品牌描述。

### 2. 首屏主会议 Hero 卡

这是本次改版的核心。

Hero 卡需要承担三件事：

1. 告诉用户首页当前最重要的动作是开始人格会议。
2. 概括会议所需的关键信息。
3. 提供明确、足够大的主 CTA。

Hero 卡内容：

1. 眉标：例如“今日主线”或“会议模式”。
2. 主标题：开始人格会议。
3. 辅助文案：说明不同人生阶段人格将围绕当前议题展开讨论。
4. 当前角色摘要：若有已选角色，展示角色名与一句简介；若未选，展示待选择状态。
5. 当前议题预览：展示当前 topic 的前一段文本，控制行数。
6. 主按钮：立即开始会议。
7. 次按钮：选择角色或调整议题。

视觉要求：

1. Hero 卡尺寸要显著大于普通功能卡。
2. 使用分层渐变、柔和高光、轻玻璃感或液态底纹，但不影响文字对比度。
3. CTA 区域必须稳定、明确，不做漂浮难点击的造型。

交互要求：

1. 整张 Hero 卡可点击进入会议配置或会议页，但主按钮仍保留独立点击反馈。
2. 当角色和人格选择已满足开会条件时，主按钮直接进入会议。
3. 当条件未满足时，主按钮引导用户完成前置选择，不报生硬错误。

### 3. 会议快速配置区

主 Hero 下方放一组轻量的会议准备信息卡，用于降低开会前切换成本。

建议包含三项：

1. 当前角色
2. 已选阶段人格数量
3. 当前议题或会议模式

布局要求：

1. 使用 2 列或 3 列紧凑卡片栅格。
2. 卡片视觉弱于 Hero，但强于普通列表项。
3. 每张卡片都应具备明确的点击去向，例如选择角色、选择阶段人格、编辑议题。

这样用户即使不离开首页，也能理解会议准备状态。

### 4. 快捷功能入口区

保留“创建角色”“寻访前人”“AI 对话”等功能，但降级为次级入口。

布局要求：

1. 以小卡片或图标卡形式呈现。
2. 控制为一行 3 个或 2 x 2 栅格，避免过多视觉重量。
3. 图标、标题、说明关系清楚，不做纯装饰化按钮。

视觉上需要与主会议 Hero 拉开等级差，避免首屏多个功能同时争抢注意力。

### 5. 最近纪要区

首页下半区展示最近一次或最近几次会议记录，用于帮助用户继续上次讨论。

内容建议：

1. 标题：最近纪要。
2. 最近一条记录以强调卡片呈现。
3. 若有更多记录，可追加轻列表。
4. 无数据时给出温和空态，不挤占过多空间。

卡片内容建议：

1. 会议标题
2. 议题摘要
3. 参与人格
4. 模式标签
5. 相对时间

## 交互与状态策略

### 主按钮行为

主按钮应遵循“优先成功启动，失败时温和引导”的逻辑：

1. 若已选角色且已满足最小人格数量，则直接进入会议。
2. 若已选角色但人格不足，则进入该角色的会议准备页。
3. 若未选角色，则跳转到角色选择入口。

### 空状态策略

1. 无角色时：Hero 卡仍保留会议主语义，但文案提示先选择角色。
2. 无会议记录时：最近纪要区展示引导性空态。
3. 接口失败时：错误展示应靠近对应区域，不应破坏整个首页层级。

### 动效策略

采用轻量动效，强调层次和反馈，不做大范围连续动画。

建议保留：

1. 首页首屏分段淡入与轻微位移动画。
2. Hero 卡按钮按压缩放反馈。
3. 快捷卡轻微抬升或高亮反馈。
4. Tab 切换时轻度透明度过渡。

避免：

1. 复杂粒子、持续漂浮动画。
2. 大面积模糊导致性能和清晰度问题。
3. 影响点击命中的装饰层。

## HarmonyOS 规范约束

本次实现需要遵循以下鸿蒙侧原则：

1. 主任务优先：首页首屏只保留一个明确主动作。
2. 触控友好：按钮、卡片、标签都要满足移动端舒适点击面积。
3. 安全区完整：继续使用 safe area，避免头部和底部遮挡。
4. 层级清晰：通过主卡、次卡、轻量信息条组织信息，不依赖过多文字解释。
5. 文本可读：渐变和背景装饰不得压低正文对比度。
6. 动效克制：优先使用系统友好的缩放、透明度、位移反馈。
7. 状态明确：连接状态、准备状态、空态、错误态都要易于识别。

## 组件与代码层改造范围

优先在现有 Harmony 首页内完成改造，尽量局部重构，不做大面积全局样式迁移。

涉及范围：

1. `harmony/entry/src/main/ets/pages/Index.ets`
2. 可能涉及首页已有组件，例如 `HeroSection.ets`、`RoleHomeActionCards.ets`、`RecordsTab.ets`、`TabBar.ets`
3. 可能新增少量首页专用子组件，用于拆分主 Hero、配置卡、纪要摘要卡

实现策略：

1. 复用现有状态字段和导航方法。
2. 优先重排现有数据展示关系，而不是创造新数据依赖。
3. 若现有组件职责与新结构不匹配，可提炼新的首页组件，但只围绕首页服务。

## 测试与验收

验收标准：

1. 首屏能一眼看出“开始人格会议”是主任务。
2. 用户能在首页理解当前是否具备开会条件。
3. 角色、快捷入口、最近纪要都有清晰承接，但不抢主路径。
4. 页面在不同状态下无明显布局断裂。
5. 保持 Harmony 端视觉一致性和触控可用性。

测试重点：

1. 有角色 / 无角色
2. 有纪要 / 无纪要
3. 连接成功 / 连接失败
4. 已选足够人格 / 人格不足
5. 不同屏幕高度下首屏内容是否拥挤

## 风险与取舍

1. 如果首页承载过多会议前配置，可能重新变回复杂工作台，因此本次仅保留轻量会议准备信息，不把完整配置塞回首页。
2. 如果 Hero 视觉过重，可能压缩其他信息可见性，因此会通过控制高度和层级来平衡。
3. 如果复用旧组件过多，结构可能受限；如果完全重写，成本会变高。因此采用“页面重排 + 局部组件重构”的折中方式。

## 最终方案结论

本次 Harmony 首页采用“会议中枢型”的首页改版方案：

1. 首页首屏以人格会议 Hero 卡作为绝对主视觉与主动作。
2. 角色状态、人格准备状态和议题摘要围绕会议启动路径组织。
3. 快捷功能与最近纪要降为承接层，形成清晰的主次结构。
4. 整体视觉采用更灵动的分层卡片与轻动效，但严格遵循鸿蒙移动端可读性与可点击性约束。
