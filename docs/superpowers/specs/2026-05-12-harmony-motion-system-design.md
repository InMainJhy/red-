# Harmony 动效系统设计

**日期：** 2026-05-12  
**范围：** Harmony 端核心页面第一轮动效统一  
**目标：** 为首页、资料、创建、会议、纪要建立统一的“灵动型”动效语言，并将页面切换转场纳入同一套视觉节奏。

---

## 1. 设计目标

这次动效优化不是给单个页面“加一点动画”，而是为 Harmony 端建立一套统一、可复用、符合当前清透卡片 UI 风格的交互节奏。

本轮目标有四个：

1. 强化页面进入时的层次感，让页面不是静态铺开，而是按信息优先级建立视觉焦点。
2. 强化卡片、按钮、列表的可操作感，让点击、切换、展开更有反馈。
3. 为核心链路增加页面转场，让“首页 → 资料 / 创建 / 会议 / 纪要”的跳转更连贯。
4. 抽出通用动效基建，避免每个页面分别写一套不同节奏的动画。

---

## 2. 动效定位

本次采用“灵动型”动效风格，基调是轻盈、柔和、连续，而不是夸张、跳跃、强舞台感。

动效特征：

- 页面进入以淡入、上浮、左右滑入为主
- 卡片反馈以轻缩放、轻下沉、阴影变化为主
- 分组内容采用短节奏错峰出现
- 页面转场采用横向滑入 + 透明过渡
- 滚动联动采用轻压缩、轻透明变化，不做重视差

不采用的效果：

- 大幅旋转
- 频繁弹跳
- 长时间拖尾
- 高对比闪烁
- 会影响阅读或输入的持续运动

---

## 3. 第一轮覆盖页面

第一轮优先覆盖可见度最高、路径最核心的页面：

1. 首页 `Index.ets`
2. 分类人物页 `ExplorePersonas.ets`
3. 创建相关页
   - `CreateRole.ets`
   - `AIDialogueCreateRole.ets`
4. 会议相关页
   - `MeetingParticipantPage.ets`
   - `MeetingChatPage.ets`
5. 纪要相关页
   - `SummaryListPage.ets`
   - `SummaryDetailPage.ets`

这轮先把上述页面做成统一体验。其它页面第二轮沿用同一套能力继续补齐。

---

## 4. 动效层级模型

全站动效采用四层结构：

### 4.1 页面转场层

负责页面与页面之间的进入、返回、替换感知。

规则：

- 前进：右侧滑入并伴随轻透明进入
- 返回：左侧退回并伴随轻透明离场
- 核心入口页与核心内容页之间转场节奏统一
- 非核心弹出层、面板、Sheet 采用底部上滑或淡入，不走全屏横滑

### 4.2 页面入场层

负责页面首次展示时的信息建立顺序。

统一节奏：

1. 顶部 Hero / 标题区先出现
2. 主要操作卡片第二组出现
3. 列表、次级信息、说明文案最后补齐

视觉方式：

- 透明度从 0 到 1
- Y 轴从 18 到 28vp 的上浮复位
- 小规模 scale 从 0.98 到 1

### 4.3 组件反馈层

负责卡片、按钮、标签、分类 Chip、列表项的操作反馈。

统一反馈：

- 按下：缩放到 0.96 ~ 0.98，轻微下沉 1 ~ 2vp
- 抬起：快速回弹到原位
- Hover/选中态：轻微放大、阴影增强、局部高光增强

### 4.4 滚动联动层

负责用户上下滑动时的轻量动态反馈。

原则：

- 不抢信息，不做连续夸张位移
- 仅在 Hero、首卡、悬浮区做细微联动
- 列表本体保持稳定，避免阅读时晃动

## 5. 关键页面动效设计

## 5.1 首页 `Index`

首页是第一优先级页面，作为“会议工作台”需要具备明显的层级建立过程。

入场顺序：

1. 顶部主卡和右上角 IP 先淡入上浮
2. “准备”工作台三卡片做错峰出现
3. “扩展”区功能卡左右交错上浮
4. “最近纪要”卡片最后补齐
5. 底部 TabBar 轻上浮出现

交互反馈：

- 会议主卡点击有轻压缩与按钮高光推进
- 工作台三卡统一按压反馈
- 扩展卡带轻微左右 reveal 感
- 最近纪要卡有轻量点击沉降感

滚动联动：

- 顶部主卡在上滑时轻微压缩与减阴影
- 右上角 IP 保持轻浮动，但不跟随大幅位移

## 5.2 分类人物页 `ExplorePersonas`

这个页面重点是“搜索 + 分类切换 + 列表浏览”的节奏感。

入场顺序：

1. 标题区与搜索栏先出现
2. 分类 Chip 横向区从左到右轻错峰进入
3. 人物卡片首屏做分组上浮出现

交互反馈：

- 分类 Chip 选中时轻放大与高亮变色
- 人物卡在按下时轻缩放，下沉 2vp
- 切换分类后列表不直接闪切，而是做短时淡出后新内容上浮进入

## 5.3 创建相关页 `CreateRole` / `AIDialogueCreateRole`

创建类页面更偏流程感，应避免“长表单静态铺开”。

入场顺序：

1. 页面头部先进入
2. 表单区块按段出现
3. 生成按钮最后建立主操作权重

交互反馈：

- 输入区聚焦时做轻量边框增强与阴影提升
- 模式切换按钮有左右滑动或淡入切换
- 生成按钮具备轻呼吸感，但仅在空闲状态下启用

## 5.4 会议准备页 `MeetingParticipantPage`

该页现在收敛为角色选择页，重点应落在“人物卡选择节奏”和“保存动作确认感”。

入场顺序：

1. 页面头部与摘要条先出现
2. 已添加人物分组依次上浮
3. 保存按钮最后出现

交互反馈：

- 角色项选中时缩放与描边增强同步
- 分组块展开、删除、添加使用短时淡入/收起动画
- 保存按钮在可保存状态下有明确亮起反馈

## 5.5 会议对话页 `MeetingChatPage`

该页最重要的是“会议被唤醒”的感觉，而不是页面直接静态落地。

入场顺序：

1. 顶部会议状态和已选人格摘要先进入
2. 对话区整体从下往上建立
3. 空态提示或第一条系统消息作为最后一层出现

消息动效：

- 新消息沿用现有气泡进入能力
- 气泡进入统一为轻上浮 + 透明度建立
- 不做横向大幅弹射，避免破坏阅读

输入区反馈：

- 输入框聚焦时顶部边缘微亮
- 发送按钮根据可发状态做透明度与缩放变化

## 5.6 纪要页 `SummaryListPage` / `SummaryDetailPage`

纪要页需要偏稳重，但不能失去系统整体灵动感。

入场顺序：

1. Hero / 标题先建立
2. 纪要列表或摘要主体第二层进入
3. 次级分析模块、标签、底部操作第三层出现

交互反馈：

- 纪要卡点击时轻缩放
- 详情内模块展开过渡用淡入 + 上浮
- 工具栏按钮采用统一轻压缩

---

## 6. 通用能力设计

本轮不建议继续每页单写一套动效，而要先补通用基建。

建议新增或整理以下能力：

1. 页面入场状态模板
   - 统一维护 `opacity / translateY / scale` 组合
2. Reveal / Stagger helper
   - 支持首屏卡片批量错峰进入
3. 页面转场封装
   - 统一核心页面的前进/返回视觉方向
4. 卡片按压反馈配置
   - 统一缩放、阴影、位移参数
5. 滚动联动参数
   - 统一 Hero 与首卡的轻量压缩/透明度节奏

这些能力应尽量放在公共样式层或可复用组件层，而不是散落在单个页面里。

---

## 7. 视觉一致性约束

为了避免动效“各做各的”，本次实现必须遵守以下约束：

1. 时长统一
   - 快速反馈：120ms ~ 180ms
   - 标准入场：220ms ~ 320ms
   - 大区块建立：320ms ~ 480ms

2. 位移统一
   - 小组件：6 ~ 12vp
   - 卡片/模块：14 ~ 24vp
   - 页面区块：18 ~ 28vp

3. 缩放统一
   - 按压：0.96 ~ 0.98
   - 入场：0.98 → 1
   - 选中强调：1.01 ~ 1.04

4. 阴影统一
   - 只用于强调交互，不用于制造夸张漂浮感

5. 动效层级统一
   - 同一页面里必须有主次，不允许所有块同时强动

---

## 8. 实现边界

本轮只做 Harmony 前端视觉与交互动效，不改业务 API，不改会议后端逻辑，不重做信息架构。

允许的调整：

- 页面入场状态管理
- 页面切换动效
- 卡片和按钮反馈
- 模块 reveal 节奏
- 局部布局微调，用于适配动画节奏

不在本轮范围内：

- 重新设计页面信息结构
- 全量改写老组件
- 新增复杂 3D、粒子、大面积连续动画
- 因动画重构业务流程

---

## 9. 验收标准

完成后应满足以下效果：

1. 首页、资料、创建、会议、纪要进入时不再是静态铺开，而有明确层级建立。
2. 首页到资料、创建、会议、纪要的主链路跳转具备统一页面转场。
3. 核心卡片、Chip、按钮都有统一按压和选中反馈。
4. 列表和分组内容进入具有轻量错峰节奏。
5. 动效与当前冰蓝清透卡片视觉一致，不突兀、不花哨、不影响操作效率。
